## Context

專案已具備回測分析主流程與多個分析分頁，但缺少可配置的動態複利模擬。需求要求同時比較每週調整與每月調整模式，並且確保 MDD 計算與圖表採樣基準一致，避免因採樣頻率差異造成比較失真。  
此外，專案存在 read-only 檢視情境，需要允許前端本地調參重算但不可持久化。

## Goals / Non-Goals

**Goals:**
- 在單一分析 API 回傳中提供 `dynamic_compounding.weekly` 與 `dynamic_compounding.monthly` 結果。
- 支援參數化切換規則（初始比例、加碼門檻、回撤切回、最大倍數封頂）。
- MDD 與曲線統一採「週浮動淨值抽樣」。
- 月模式結果也對齊到週節點輸出曲線，確保同軸比較。
- 前端提供即時編輯重算與規則說明（Help）。

**Non-Goals:**
- 不新增獨立資料表儲存逐點曲線。
- 不引入新的回測引擎或交易資料格式。
- 不在本次變更處理多幣別轉換。

## Decisions

1. 在分析請求 options 新增 `dynamic_compounding` 設定物件，並於後端正規化預設值。  
理由：可沿用既有 analyze 流程，不需新增 API。

2. 模擬以 period 模式控制持倉切換（週/月），但淨值路徑使用浮動資料點計算。  
理由：保留策略切換語義，同時避免月模式忽略週內變化。

3. MDD 與 curve 改為週抽樣輸出。  
理由：統一比較基準，降低每日/逐筆噪音，並符合需求「不用每日，用週淨值即可」。

4. MDD(%) 採點對點回撤比例最大值：`max((peak_before_i - equity_i) / peak_before_i)`。  
理由：避免使用全域最終高點做分母而低估歷史回撤比例。

5. 前端 read-only 模式下允許編輯並觸發分析，但不呼叫持久化設定 API。  
理由：滿足「可檢視專案也能試算」需求。

## Risks / Trade-offs

- 週抽樣會低估週內尖峰回撤 → 以需求指定為準，並於 spec 明確定義抽樣標準。
- 月模式改為週節點對齊後，結果可能與舊版不一致 → 以新規格作為唯一比較口徑，更新測試基準。
- 參數極端值可能導致超大數字顯示 → 前端格式化與上限封頂保護。
