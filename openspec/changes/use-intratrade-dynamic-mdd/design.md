## Context

目前 `_simulate` 以每筆交易更新 `logic_peak` 並用它判斷百分比回撤回切，但 MDD 僅在 `_flush_week_sample` 以每週最後一筆淨值更新。兩者高點集合不同，因此回切事件與報表 MDD 可能互相矛盾。輸出曲線的週抽樣是既有 UI 比較基準，不需要因 MDD 口徑調整而改變。

## Goals / Non-Goals

**Goals:**

- MDD 金額、百分比與日期使用每筆交易後的浮動淨值。
- MDD 與回切判斷共享同一種逐筆高點定義。
- 每週、每月模式的 MDD 都能捕捉調整期間內的高低點。

**Non-Goals:**

- 不改變回切、恢復或加碼的時點。
- 不改變週抽樣 Equity Curve。
- 不改變 API 欄位或前端表格結構。

## Decisions

- 在每筆 `step_pnl` 更新 `equity` 後立即更新逐筆 MDD，再處理曲線週抽樣。這能保存逐筆高點至低點的完整路徑，且與 `logic_peak` 的更新粒度一致。
- MDD 使用獨立的 `mdd_peak`，而不直接重用 `logic_peak`。兩者目前定義相同，但分離狀態可避免未來回切狀態機變更意外改動報表指標。
- `_flush_week_sample` 僅產生曲線點；其中的 `drawdown_amount` 仍可相對逐筆 `mdd_peak` 顯示當週末距離歷史逐筆高點的回撤，但不再負責彙總 MDD。
- 無 `points` 的相容路徑也在期末淨值更新後執行相同的 MDD 更新。

## Risks / Trade-offs

- [既有專案的 MDD 可能提高，且日期改變] → 維持欄位名稱並在規格中明確定義為逐筆 MDD；部署不需資料遷移，重新分析即生效。
- [曲線點無法直接重建表格中的逐筆 MDD] → 這是保留週抽樣曲線的刻意取捨；若需稽核逐筆路徑，後續可另增明細輸出。
- [同日多筆交易的排序會影響逐筆 MDD] → 沿用合併交易既有的穩定排序，與回切內部高點的現行行為一致。
